# Glim iOS

Клиент соцсети Glim на SwiftUI. Код написан под реальный API
`blik-server` — роуты и форматы сверены с исходниками.

## Что учтено из серверной части

**Авторизация — cookie-сессия, не токены.** Сервер ставит куку `blik_sid`
(HttpOnly, 90 дней) и проверяет её через `loadSession()` в `src/session.js`.
Никаких Bearer-заголовков в коде нет — всё делает `HTTPCookieStorage`
в `URLSession`. Это же значит, что после выхода нужно чистить куки, иначе
сервер будет считать сессию живой.

**Вход только по почте и в несколько шагов.** Флоу в `auth.js` такой:

```
POST /api/auth/start    { channel: "email", to: "..." }   → отправили код
POST /api/auth/verify   { channel, to, code }             → { next: ... }
```

Поле `next` говорит, что дальше: `profile` (новый аккаунт),
`password` (облачный пароль), `totp` (аутентификатор) или `done`.
Между шагами сервер выдаёт `ticket` — без него следующий запрос не примут.
Кода на почту нет — регистрация закрыта флагом `signupOff`.

**Ответы без обёртки.** Не `{ data, error }`, а просто объект. Ошибки —
`{ error: "код", message: "текст для человека" }` с HTTP-статусом.
Сообщения приходят на русском, поэтому `APIError` их показывать готов.

**Все роуты под `/api/`**, параметров `page`/`limit` нет — пагинация
курсором `before` по id поста, по 40 записей за раз.

**Формат поста богаче, чем «текст плюс лайк».** Есть `kind`
(plain / card / photo / poll), реакции эмодзи вместо лайка, карусель
изображений, опросы, комментарии прямо внутри объекта поста.

**Идентификаторы — числа**, не строки (SQLite rowid).

## Структура

```
Glim/
├── App/                    точка входа и вкладки
├── Core/
│   ├── Auth/               SessionStore — состояние входа
│   ├── Network/            APIClient, Endpoint, APIError
│   └── Models/             User, Post, Auth
└── Features/
    ├── Auth/               вход по коду из письма
    ├── Feed/               лента, пост, создание записи
    └── Profile/            профиль, подписка, выход
```

## Что нужно поправить перед сборкой

**Адрес сервера** — в двух местах, они должны совпадать:

```swift
// Core/Network/APIClient.swift
init(baseURL: URL = URL(string: "https://example.com")!)

// Core/Models/Post.swift
static let baseURL = "https://example.com"
```

Второй — для картинок: сервер отдаёт только имя файла, полный адрес
собирается как `/media/<имя>`.

**Минимальная версия iOS 17** — используются `@Observable`,
`ContentUnavailableView` и `.onChange` с новым синтаксисом.

## Как собрать

Исходники — файлы Swift, а не готовый `.xcodeproj`. Создай проект:

1. Xcode → File → New → Project → iOS → App
2. Product Name `Glim`, Interface SwiftUI, Language Swift
3. Удали созданные `ContentView.swift` и `GlimApp.swift` — точка входа уже есть
4. Перетащи папки `App`, `Core`, `Features` в проект,
   при добавлении выбери `Create groups`
5. Deployment Target: iOS 17

Проверить, что всё компилируется без Xcode под рукой, можно через
`.github/workflows/ios.yml` — он собирает на macOS-раннере GitHub.

## Что проверено, а что нет

Сверено с исходниками сервера: пути роутов, имена и типы полей,
структура ответов, схема авторизации, ограничения (500 символов на пост,
40 записей на страницу, 5 постов в минуту).

Не проверено на живом сервере — компиляции и реальных запросов не было,
поэтому первые запуски почти наверняка потребуют правок. Наиболее
вероятные места: имена полей, которых нет в части постов (например,
`stars` появляется только если таблица существует), и обработка
опциональных полей в `User`.

## Что сделано во второй итерации

Добавлены чаты, поиск людей и realtime.

**Realtime — это SSE, не WebSocket.** Сервер держит поток на `GET /api/events`
и присылает события строками `event:` / `data:`, плюс `: ping` каждые
25 секунд, чтобы канал не закрыл прокси. `EventStream` читает поток
через `URLSession.bytes(for:)` и переподключается сам при обрыве.
Соединение одно на приложение — `RealtimeService`, события раздаются
экранам через `NotificationCenter`.

**Список чатов и переписка.** Строка списка показывает последнее
сообщение, счётчик непрочитанных, галочки прочтения и точку «в сети».
В переписке — пузыри со скруглением по стороне отправителя, ответы
на сообщения, реакции, «печатает…», голосовые с формой волны, видео,
файлы, фото и стикеры. История подгружается вверх по курсору `before`
(сервер отдаёт по 100 сообщений).

**Загрузка вложений.** Сервер ждёт сырые байты в теле, а не JSON,
и требует заголовки `x-blik-upload: 1` и `x-file-name`. В ответ приходит
путь `/media/xxx.jpg`, который кладётся в `data.url` сообщения.
Правила сервера: фото — JPG/PNG/WEBP/GIF, голосовые и видео — WEBM/OGG/MP4,
всё остальное уходит как файл. Есть суточный лимит на пользователя.
